# TUM Calendar Proxy (TypeScript)

A self-hosted proxy for the TUMonline iCal export, based on
[TUM-Dev/CalendarProxy](https://github.com/TUM-Dev/CalendarProxy). It serves a cleaned-up calendar feed and a web UI to:

- **rename courses**: automatic short names (e.g. *Einführung in die Rechnerarchitektur* → *ERA*), or your own
- **hide courses**, single **series** (a tutorial group or time slot), or **single events**
- add **notes** to events (shown at the top of the event description)
- add **NavigaTUM** room links and real street addresses (so Apple/Google Maps can find the building)
- merge the duplicate events TUMonline creates for lectures held in several rooms

Every event in the feed links back to its page on the proxy. Tap the link in your calendar app to hide the event,
its series or the whole course, or to add a note. The change shows up after the app's next refresh.

## How login works

There are no accounts. Your TUMonline calendar link (`pStud`/`pPers` + `pToken`) is the login:

- The **feed URL** (`/cal.ics?pStud=…&pToken=…`) and the **login link** (`/?pStud=…&pToken=…`) carry the token.
  The server never writes it to disk.
- The browser keeps it in `localStorage` and sends it with each API request.
- The server stores your settings in `data/feeds/<sha256(id:token)>.json`. It only needs the hash to find them;
  without the token, nobody can read or change them.
- Your calendar is fetched from TUMonline on demand and cached in memory for `CACHE_TTL_SECONDS`.

Both links give access to your calendar, so keep them private. The settings file contains course names and notes,
but no ID or token.

## Run with Docker

```sh
docker compose up -d --build
```

Open <http://localhost:4321>, paste your TUMonline calendar link (TUMonline → Calendar → Publish), and subscribe to the
feed URL shown (iOS: Settings → Calendar → Accounts → Add Subscribed Calendar).

For the event links to work on your phone, the server must be reachable from it: run it behind a reverse proxy with
HTTPS and set `PUBLIC_URL`.

| Variable            | Default | Description                                                                                       |
| ------------------- | ------- | ------------------------------------------------------------------------------------------------- |
| `PUBLIC_URL`        | –       | Base URL used in feed and event links, e.g. `https://cal.example.com`. Derived from the request (incl. `X-Forwarded-*`) if unset. |
| `REGISTRATION`      | `open`  | `closed`: only calendars that already logged in once can use the server. Log in once, then close it. |
| `CACHE_TTL_SECONDS` | `300`   | How long a fetched TUMonline calendar is reused.                                                  |
| `PORT`              | `4321`  |                                                                                                   |
| `DATA_DIR`          | `/data` | Where settings are stored (a volume in `docker-compose.yml`).                                     |

## Deploy behind Traefik

[`deploy/docker-compose.yml`](deploy/docker-compose.yml) runs the published image behind an existing Traefik instance
(external Docker network, HTTPS entrypoint and certificate resolver):

```sh
mkdir tum-calendar && cd tum-calendar
curl -O https://raw.githubusercontent.com/danielgnth/tum-calendar-proxy/main/deploy/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/danielgnth/tum-calendar-proxy/main/deploy/.env.example
$EDITOR .env      # DOMAIN plus your Traefik network, entrypoint and resolver names
docker compose up -d
```

If Traefik access logs are enabled, they record request URLs including the `pToken` query parameter of feed requests.
Drop or redact the `RequestPath` field there if that matters to you.

## Image, SBOM and signature

[`.github/workflows/image.yml`](.github/workflows/image.yml) tests the code and builds `linux/amd64` and `linux/arm64`
images. On pushes to `main` and `v*` tags it publishes them to `ghcr.io/danielgnth/tum-calendar-proxy` and:

- attaches BuildKit SBOM and provenance attestations,
- signs the image keylessly with cosign (GitHub OIDC, recorded in the Sigstore transparency log),
- attests an SPDX SBOM generated by Syft with cosign, and uploads it as a workflow artifact.

Tags: `latest` (main), `1.2.3` and `1.2` (from tag `v1.2.3`), and `sha-<short>`.

Verify an image before running it:

```sh
IMAGE=ghcr.io/danielgnth/tum-calendar-proxy:latest
ID='^https://github.com/danielgnth/tum-calendar-proxy/\.github/workflows/image\.yml@'
ISSUER=https://token.actions.githubusercontent.com

cosign verify "$IMAGE" --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISSUER"
cosign verify-attestation "$IMAGE" --type spdxjson --certificate-identity-regexp "$ID" --certificate-oidc-issuer "$ISSUER"
```

## Development

Requires Node 24+ (runs TypeScript directly) and pnpm.

```sh
pnpm install
pnpm dev        # API on :4321, UI with hot reload on http://localhost:5173
pnpm test
pnpm typecheck
pnpm build && pnpm start
```

```
src/server/clean.ts      title shortening and building lookup (data/courses.json, data/buildings.json)
src/server/pipeline.ts   applies the settings to a TUMonline calendar
src/server/app.ts        HTTP routes: /cal.ics, /api/*, web UI
src/server/store.ts      settings files and validation
src/shared/types.ts      types shared with the UI
web/src/                 React UI (dashboard and event page)
```

To add short names for more courses, edit `src/server/data/courses.json`.
